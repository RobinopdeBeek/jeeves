## Problem Statement

After fan-out (slice 7), child tasks sit with `plan: pending` and never run. Standalone tasks can enqueue Plan, but the engine only has a tracer Plan skill, always bases worktrees on hardcoded `main` with `git worktree add -B` (which would wipe Implement commits on the next step), does not chain Plan → Implement → AI Review, and has no path into Human Review. The board cannot yet demo an unattended vertical slice the way interactive `/implement` feels — light plan, TDD implement, code-review then rework — split across monitorable steps.

## Solution

Ship the full Implement Task pipeline as `/implement` split across three context windows, then land the card in the Review column via an explicit **Prepare Eval** step (stubbed in this slice; real assemble in slice 9).

A child or standalone task runs **Plan → Implement → AI Review** unattended on one durable card branch (fresh worktree per run). AI Review does dual-axis Standards + Spec review and immediately reworks once, writing a concise markdown overview. Host-owned `verify_commands` gate green builds. The card then enters Review with **Prepare Eval** queued (stub finishes and unlocks human Review). The Implement tab shows a GitHub-like lazy per-file diff (assistant-ui DiffViewer) of the card branch vs upstream. Depth-first queue ordering runs one task's three steps before the next sibling's Plan.

**Baseline (landed):** Project Chat / app shell (#33) shipped in [PR #54](https://github.com/RobinopdeBeek/jeeves/pull/54). Slice 8 builds on that code; it does not re-implement Chat. Build-order items 15–18 describe Chat work that already landed early — treat them as done, not as blockers ahead of this slice.

## Implementation Decisions

- **Product shape:** Implement Task = interactive `/implement` split into Plan (light planning + Context7 when available), Implement (`/tdd`), AI Review (`/code-review` shape + immediate one-pass rework). Evaluation is **not** produced in AI Review; it is produced by **Prepare Eval** (`prepeval`) in the Review column before human Review ([`0015-ai-review-reworks-eval-on-human-review-entry.md`](docs/adr/0015-ai-review-reworks-eval-on-human-review-entry.md)). **Note:** PR #54 also added `docs/adr/0015-project-chat-threads-and-chatsession.md` (same number). Prefer the **filename** above for slice 8; renumber the chat ADR series in a separate docs fix so “ADR 0015” is unambiguous again.
- **Modules:** `PipelineEngine`, `ExecutionEngine`, `WorktreeManager`, `CardStore`, thin HTTP/UI adapters. Prefer existing seams; extend rather than invent parallel orchestrators.
- **`PipelineEngine.advance`:** On `step-finished` success: `plan` → done + `impl` queued + enqueue impl; `impl` → done + `airev` queued + enqueue airev; `airev` → done, column → `review`, ensure `prepeval` queued + `review` pending, enqueue `prepeval`. Failure → that step `needs-user`, no enqueue. Extend `AdvanceSideEffect` so `enqueue` carries target `cardId`; add `ensure-branch` for the feature at fan-out.
- **Fan-out:** Create/record feature branch (`ensure-branch`); set unblocked children `plan: queued` and emit per-child enqueue effects; blocked children remain `plan: pending`. No fake unblock in this slice.
- **Queue:** One run at a time. Eligible = `queued` and no unmerged blockers. Order by `(sibling position, step index plan < impl < airev < prepeval)` for depth-first per task. Rebuild from DB on boot (no in-memory front-insert as source of truth). Orphaned `running` runs → failed; steps → `needs-user` (existing boot behavior retained/extended).
- **WorktreeManager:** Split seam into `createFrom(baseSha)` (first branch creation) and `checkoutExisting(branch)` (continuation at tip). Do not use `-B` with upstream SHA on continuation. Retry uses recorded run `base_sha`.
- **Branch timing:** Feature branch at fan-out; standalone/child lazy on first Plan; persist `cards.branch`. Child base = parent feature branch tip; standalone/feature base = `projects.default_branch` resolved SHA.
- **Schema:** Add `projects.default_branch`, `projects.verify_commands` (ordered JSON/text commands; null/empty skips with warning). Add step key `prepeval` (and extend any parallel step-key enums from #54, e.g. `cardAttachments.originStep`). Add artifact kind `review`. Persist `cards.branch` when created (`cards.branch` column already exists nullable).
- **Step policies:** Plan — harvest `.jeeves/plan.md`, no source commits. Implement — ≥1 commit, clean tree, then host verify. AI Review — harvest `.jeeves/review.md` (concise markdown), zero or more commits allowed, clean tree, verify if commits. Prepare Eval stub — produce minimal placeholder eval (or equivalent postcondition) with no source commits; succeed into human Review `needs-user`.
- **Prompts:** Retire slice-3-tracer for production Plan. Real `plan-implementation`, `implement-task`, `ai-review` under `prompts/execution/`. Inject pipeline inputs explicitly (card fields, parent spec, plan path, diff/upstream as needed, manifest). **Do not** inject Card attachments / Info library files in this slice (deferred).
- **SDK runner:** Enable appropriate `settingSources` so MCP/Context7 can load; missing Context7 is non-fatal for Plan.
- **UI:** Plan and AI Review keep `StepExecution` (live log → collapsed frozen log + markdown artifact). Implement: same log behavior + DiffViewer body when done. Diff API: list files+stats for `upstream...cardBranch`, lazy per-file patch; soft size warning + Load anyway. Default unified view. Label or show resolved SHAs so the range is attributable. DiffViewer is **not** yet a dependency after #54 — adding the package is part of slice 8.7 (#63).
- **Rounds:** Keep `currentRound` at 0 for this slice.
- **Docs:** Grill PR #51 updated CONTEXT / plan docs for this flow; implementers must not contradict [`0015-ai-review-reworks-eval-on-human-review-entry.md`](docs/adr/0015-ai-review-reworks-eval-on-human-review-entry.md) / CONTEXT. Chat ADRs from #54 are out of scope except the numbering collision note above.

## Testing Decisions

- Test **external behavior** at the highest seams only: `PipelineEngine.advance`, `ExecutionEngine` (queue order, base resolution, policies, verify gate, boot rebuild), `WorktreeManager` createFrom/checkoutExisting, `CardStore` fan-out/effects/project fields. Do not assert React trees, SDK wire protocol, or prompt prose quality.
- Good tests: given card/step state and fakes for git/runner/artifacts, assert resulting patches, side effects, run outcomes, and branch SHAs — not private queue array shape.
- Prior art: `server/pipelines` tests, `server/execution/engine.test.ts`, `worktree-manager.test.ts`, `cards/store.test.ts` (fan-out), step-policy tests, route adapter tests that only dispatch effects.
- Thin adapter checks: diff API returns file list and per-file patch shape; optional lightweight routing/UI smoke if already patterned elsewhere — not full browser E2E required for v1.
- Do not claim Context7 works without a recorded env/spike; test non-fatal path when MCP unavailable.
- Prepare Eval stub: assert advance into Review and human `review` needs-user after stub success; do not require full eval HTML sections (slice 9).

## Out of Scope

- Approve/merge, temporary merge check, blocker release on merge (slice 10).
- Full eval section skills beyond the stub (slice 11).
