## What to build

Continuation agent runs must not reset a card's durable branch to upstream and wipe Implement commits. First run creates the branch from an explicit base; later runs check out the existing branch tip; retry of a failed run recreates from that run's recorded base SHA. Projects gain an explicit local default branch instead of a hardcoded `main`.

Still required after #54: `WorktreeManager.create` still uses `git worktree add -B`; `projects` has no `default_branch` yet. `cards.branch` already exists as a nullable column — this ticket persists it when the branch is first created.

## Agent size

M — extends WorktreeManager + ExecutionEngine with an established pattern; adds `projects.default_branch`.

## Verification

CI only

## Acceptance criteria

- [ ] Worktree lifecycle seam distinguishes create-from-base vs checkout-existing-branch (continuation cannot pass an upstream reset SHA through the create-from path)
- [ ] First run for a card without a branch: resolve upstream (`projects.default_branch` for standalone/feature base, parent feature branch tip for child), create branch, persist `cards.branch`, record `base_sha` on the run
- [ ] Later runs on the same card: check out existing branch at tip (no `-B` reset to upstream)
- [ ] Retry of a failed run recreates from that run's recorded `base_sha`
- [ ] `projects.default_branch` exists and is used instead of hardcoded `main`
- [ ] Existing Plan tracer path still works under the new base resolution (no behavior regression for slice 4 demos)
